# ADR 0009 decisions log

Working notes, not product docs ([publishing policy](../../../docs/publishing.md)).
Decisions taken while building the shared session engine and the native
SDKs on the `adr-0009-shared-engine` branch. Rule for this milestone: when a
choice would change shipped behaviour (Flutter fingerprints, existing event
fields, the `capture-runtime` / `TugboatCaptureRuntime` ABI, Flutter
defaults), take the option that leaves it unchanged and record it here.

## Milestone

Native Android (Views + Compose) and SwiftUI SDKs on the session engine, each
with an in-repo sample app, sending real sessions to a local collector and
passing device tests on the emulator and simulator. The Flutter adapter keeps
its Dart path unchanged. No publishing and no merges to `main`.

## Gates before merging to main

1. On merge to `main`, `publish-android.yml` (`tag_main`) auto-tags and
   publishes `capture-runtime` 0.3.0, then opens an automatic Flutter pin PR.
2. That pin PR compiles: the plugin maps `SecureWindow` to `cancelled` and
   `WindowComposite` to the existing Pigeon value (`tugboat`
   0.10.11-dev.2), and `android-runtime.yml` compiles the plugin against the
   pinned and the local runtime, which must pass against `capture-runtime`
   0.3.0 (0.3.0's additions are additive with defaults). The `main` PR description must
   still say that merging publishes `capture-runtime` 0.3.0; the owner
   decides at merge time.
3. The instrumented window-capture tests
   (`:capture-runtime-test:connectedAndroidTest`) must have run on an
   emulator or device. CI runs them on API 26 and 34
   (`android-runtime-device.yml`).
4. On merge to `main`, the Apple publish flow tags `apple-runtime-v0.2.0`
   and pushes `TugboatCaptureRuntime` 0.2.0 to CocoaPods trunk (the root
   podspec `s.version` is 0.2.0 and not on trunk), then opens a Flutter pin
   PR (`open-flutter-apple-pin-pr.sh`). 0.2.0 adds no enum cases, so the
   plugin's Swift compiles against it. The `main` PR description must say so.
5. On merge to `main`, `publish.yml` tags `v0.10.11-dev.3` and publishes
   `tugboat` and `tugboat_dio` 0.10.11-dev.3 (lockstep prerelease) to
   pub.dev. Prereleases are not selected by `^` constraints. The owner can
   instead choose a stable 0.10.11 for both before merging.
6. Not published by the merge: `tugboat-android` and `tugboat-compose`
   (`publish-android.yml` runs only `:capture-runtime` tasks), the Swift
   `Tugboat` / `TugboatSessionEngine` SwiftPM products (no tag of their
   own; the `v0.10.11-dev.3` pub tag points at a commit whose root
   `Package.swift` declares them, so SwiftPM could resolve that prerelease
   tag), and no `TugboatSDK` podspec exists.

## Open items

- **Engine `session_start` navigation kind.** Flutter 0.10.10 seeds the visible route at session start (`navigation: session_start`); add an equivalent engine fact before Flutter moves onto the engine.
- **Engine: capture on a boundary change.** A `surface` generation change
  could request a forced capture, so the first interaction after a rotation
  or resize has a compatible before-frame and a `position` (today it has
  none).
- **Engine "delivery settled" signal** (see the delivery row): replaces the
  host-side retry-rule copies used by `stop()`.
- **SwiftUI layer allowlist for iOS 15–25.** Only iOS 26 is verified. Re-run
  `spike/swiftui-a11y-probe` on each older major version that the SDK must
  support with per-layer masks; until then those versions mask the whole
  frame.

## Open cross-repo questions

- **Q2: wire idempotency.** Batches, frames and lifecycle posts need an
  idempotency key the collector deduplicates on before a durable outbox or
  retry backoff (C4) can ship.
- **Native backend names.** `frameMetadata` backend is a closed enum
  (`flutterRepaintBoundary` | `nativeCpuExperimental`) on the collector.
  Native SDKs reuse `nativeCpuExperimental` until the collector adds native
  backend names.
- **Collector `frame_captures.triggeredAt` is 1970.** pmkit-collector's
  `src/domain/frame-captures.ts` reads `frameMetadata.atMs` as epoch
  milliseconds, but it is session-relative (as Flutter's `TugboatFrame.atMs`).
  Collector fix: session start + `atMs`. Not an SDK change (found in the
  PR #95 device test).
